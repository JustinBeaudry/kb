# Memory observability

`platform.NewTelemetry(writer, serviceName, exporters...)` supplies the process JSON `slog` logger and a private OpenTelemetry provider. Service names are the closed set api/worker/graph/admin. Composition owns one instance per process, supplies it to handlers/workers/gateways and calls `Shutdown` during graceful termination. No exporter endpoint or backend credential is discovered implicitly. Exporter failures are normalized before the SDK global error handler; a closed telemetry_export_failed JSON event replaces arbitrary vendor error prose. Exporting requires an explicitly configured trusted exporter; absence means no trace backend delivery claim.

Logger configuration enforces a closed schema for messages and attributes, including `With` and `WithGroup`. Arbitrary message/error strings, source bodies, object identifiers, vendor responses, URLs, endpoints, bearer values, key IDs and nested payloads are discarded. Safe status/method/duration/capacity counters and closed reason codes remain. Redaction is not a caller-by-caller convention. Do not add an unfiltered SDK/Neo4j logger or dump config in error paths.

`HTTPMiddleware` creates a fresh random request ID, records bounded method/status and duration, and returns `X-Request-Id`. `HTTPClientTransport` propagates that ID plus W3C traceparent, leaves the caller request unchanged and ends a client span after body EOF/Close. It does not record URL/host/path/query/header/body/error text, accept arbitrary incoming request IDs or propagate baggage/tracestate. This wrapper replaces unsafe default HTTP instrumentation attributes. `TraceIO` accepts only closed graph/object/journal lifecycle operation codes and records safe failure status without error prose; instrument DB lifecycle at composition/adapter boundaries. It does not record Cypher statements/parameters.

Public `/livez` and `/readyz` disclose only booleans and closed reason codes. They must never disclose private fence IDs, instances, object names, endpoints, backup IDs or key IDs. Liveness performs no dependency I/O. The public API serves readiness from an immutable cached report: one lifecycle-owned admitted probe starts after startup admission finishes, then waits 30 seconds after each completion before the next probe; probes never overlap. Requests perform no dependency I/O and cannot cancel or trigger sampling. Startup, stopped or reports more than 90 seconds old fail closed. Readiness may lag a maintenance/dependency transition; request admission remains immediately authoritative. The sampler is canceled and joined before database connections close. Private graph/host operational probes remain synchronous and admitted; closed probes do not touch graph or objects. Open probes check graph, evidence, journal continuity and required recovery keys. Missing optional model routes does not block this deployment.

Authenticated private control/host status provides maintenance phase, active/unknown operations, last successful backup/age and journal sequence/capacity. Alert on ready=false, unknown operations, fresh-head failures, backup age approaching24h and journal sequence≥9000. Sequence10000 is a hard closed limit. Do not append journal records to report telemetry. Monitor actual service CPU/RAM/scratch utilization to validate sizing; no log line proves recoverability.

For a failure, first inspect private supervisor status and its safe stage code, then follow [deployment](deployment.md) or [recovery](recovery.md). Missing historical journal requires restoring independent credentials/storage; never rerun init. Maintenance refusal requires waiting for the existing operation/status. Unknown backup/delete outcomes require the same operation ID and exact input. No timeout removes an unknown permit. Public liveness can stay healthy throughout a closed recovery.

CI stores race/test events and deduplicated whole-module coverage. `TestTelemetryContainsNoFixtureSecrets` checks fixture prose/credentials do not enter structured logs or exported spans. Test success, image user/tool qualification, provider capability probes, deployment health and authenticated restore acceptance are distinct evidence.
