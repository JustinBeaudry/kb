# E1: Reusable evaluation fixtures and runner

Scope: `evals/` only, plus this report. No production, skill or command documentation changed in E1.

## Delivered

- `evals/run.ts`: 20 deterministic contract scenarios against a configurable real CLI root. The fixed expectations are separate from observed output. It saves full stdout/stderr, exit code, complete-wire bytes and a single command latency sample, along with Bun/package/source/evaluator versions.
- `evals/fixtures.ts`: synthetic vault factory and knowledge snapshots. Input facts include supported/unsupported transcripts, superseded/conflicting dates, Unicode, long multiline content, a single oversized line and injected source instructions.
- `evals/provider.ts`: local deterministic stdin/argv recorder; no external calls or model quality claims.
- `evals/scenarios.json`: 20 actual-agent tasks with prompts, input evidence, expected outcomes and allowed writes. Retrieval, paraphrase, uncertainty, absence, trust boundaries, duplicate ingestion, interrupted extraction and missing optional tools are covered.
- `evals/prepare.ts`: creates a fresh isolated fixture and `task.json` for a selected actual-agent task. Expected outcomes are explicitly withheld from the solving agent, then used for assessment.
- `evals/README.md`: runner usage and evidence rules distinguishing contract results, actual agent behavior and model quality.

## Commands for C1/C2

```sh
bun evals/run.ts --label baseline --out docs/plans/2026-10-16-portable-agent-workflows/reports/baseline-evals.json
bun evals/run.ts --label current --out docs/plans/2026-10-16-portable-agent-workflows/reports/current-evals.json --compare docs/plans/2026-10-16-portable-agent-workflows/reports/baseline-evals.json
```

Use `--cli-root /path/to/base-checkout` if the base lives elsewhere. The **same runner** must evaluate each source version; comparison refuses a changed evaluator/corpus hash. Exit 1 is expected for the baseline contract failures and still saves the report. Root owns those executions and artifacts.

Expected baseline failures, to be verified by C1: Claude user/Codex/generic turns missing; unsupported content reported complete; vendor arguments imposed on a custom executable; configured argument list ignored; empty/invalid summary output accepted; oversized `get`/`get-node`/`recall` wire output; oversized single-line read; eager fallback for absent or invalid config. Legacy transcripts, canonical shell-only retrieval, explicit absence, Unicode and missing-provider failure should remain useful controls.

The multiline fixture is below the existing 256 KiB file cap and deliberately large enough to exceed the 16 KiB response budget. The single-line fixture accepts either bounded truncation or a nonzero empty-stdout failure identifying the line and `--budget` remedy. Continuation expectations use I2's agreed `policy.continuation = {command, args}` contract.

## Actual-agent trial preparation

```sh
bun evals/prepare.ts --scenario A01-known-fact --cli-root /path/to/base-checkout
bun evals/prepare.ts --scenario A01-known-fact --cli-root /path/to/current-checkout
```

Give each agent the selected version's skill, prompt and fixture/CLI configuration, then save answer, commands and before/after hashes. Record the real model/harness conditions and only metrics actually exposed by that harness. The fixture provider remains synthetic, so summarizer reasoning quality is outside scope.
