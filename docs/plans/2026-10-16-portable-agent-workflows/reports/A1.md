# A1: Actual agent task comparison

## Result

All six selected tasks produced correct, evidence-supported answers in each of three conditions: original base, initial portable implementation, and refined portable instructions. None of the 18 trials made an unauthorized knowledge change. These results establish a useful smoke test in the available host, not best-in-class or cross-harness superiority.

The initial implementation exposed an agent-efficiency regression that the contract suite could not detect. The long-page solver fetched a broad H1, raised the budget twice past the host's display limit, then paged the entire page: 17 CLI calls and 605,678 stdout bytes, versus baseline 4 calls and 419,678 bytes. D1 correction 1 teaches question/heading-specific lookup before broad reads, pagination, or budget increases; distinguishes CLI wire limits from host display truncation; and stops at sufficient evidence. A fresh solver then answered correctly in 2 calls and 1,126 bytes. All initial evidence is retained.

Efficiency is mixed on the small tasks. The refined changed-decision trial used 7 calls versus the baseline's 2, and the no-filing question used 5 versus 4. The absence task improved from 9 to 6. This single-sample comparison does not establish lower latency, fewer calls, or lower token cost in general. It identifies repeated narrow lookups after sufficient evidence as a remaining tuning opportunity for a larger, held-out evaluation.

## Conditions and reproducibility

- Original source: `2702a532d330d53bbc8e54ba18fb0e09e8631e0b`, archived separately from the working tree.
- Six scenarios were selected before observing the initial answers. The final six repeat those same scenarios after a documented instruction correction; they are development cases, not a held-out benchmark.
- Every trial used a fresh synthetic vault and fresh agent context with expected outcomes withheld. Solvers received the selected skill, prompt, CLI wrapper and fixture locations. No implementation history was supplied.
- Available host: Codex child agents, inherited serving model. The collaboration API did not expose an exact model/version identifier, tokens, or cost. Shell/file tools were required by task instruction; this was not an OS-enforced sandbox.
- CLI wrappers used an explicit environment without qmd, native hooks, MCP or credentials, and recorded actual argv, stdout, stderr, exit status, bytes and elapsed time. Summary generation used a deterministic local provider, so no summary-reasoning quality is measured.
- Initial and refined skill trees are frozen under `evidence/agent-instructions/`. Refined entrypoint SHA-256: `9e8e1ac06680dbee5222a55d911d02b7049702ebe1ddd7fed2eb3677fbf46aef`.
- `A1-agent-trials.json` holds all 18 observations and allowed writes. `evidence/agent-trials/{base,current,refined}/` holds normalized answers, activities, full CLI recordings, solver inputs, and knowledge hashes. `evidence/agent-trial-paths.json` records the original local fixture locations.
- These trials preceded R1's malformed-discriminator and retrieval implementation corrections. The refined skill itself is unchanged. The final source is verified by the regression, contract and distribution gates; no additional agent-quality result is inferred from those later code checks.

## Next evidence needed for a best-in-class claim

Run the full 20-task corpus with repeated trials across independently chosen agents/harnesses, then add held-out tasks from realistic vaults. Include ingestion and interrupted-extraction outcomes, summary quality with real configured providers, sufficient-evidence stopping, large-vault latency, tokens and cost where the harness exposes them. Keep those measurements separate from the 20 deterministic portability contracts. No external model spending or cross-harness run was authorized for this increment.
