## Contract decisions

The root accepted these interface decisions before implementation:

- Generic JSONL messages use top-level `role: "user" | "assistant"` with `content` as a string or text blocks. `type: "message"` is optional. Text blocks use `text`, `input_text`, or `output_text` as their type and a string `text` field.
- Existing `type: "human" | "assistant"` plus `message.content`, Claude-style `type: "user"`, and Codex `type: "response_item"` plus `payload.type: "message"` are supported.
- Codex `event_msg` records are ignored, preventing mirrored user/assistant events from duplicating the `response_item` stream. Tool records, metadata, system roles, images, and non-text content blocks are ignored.
- When a hash-valid nonempty transcript has no supported conversation text, use a nonempty manifest excerpt with `degraded: true`; if no usable excerpt exists, fail before provider invocation. Never generate apparently complete summaries from empty input.
- A recognized malformed conversation record alongside usable conversation text keeps the valid text and reports `degraded: true` in the result and cache frontmatter. The fixed fixture uses a Codex user message with numeric `content`. Ordinary metadata and tool records do not imply degradation.
- `KB_SUMMARIZE_COMMAND` names an executable. Custom executables receive no implicit vendor flags. `KB_SUMMARIZE_ARGS` is a JSON string array, passed literally without shell expansion. Malformed JSON, non-array values, and non-string elements fail before invocation.
- Default Claude behavior remains a convenience fallback. Proposed implementation semantics: `KB_SUMMARIZE_ARGS`, when present, replaces the argument list for either the custom executable or the default command; absent custom arguments leave the default Claude invocation at `-p --model haiku`.
- `KB_SUMMARIZE_TIMEOUT_MS` is a positive integer in milliseconds with a default of 120000. The timeout error names this setting. The test uses 100 ms against a provider that would otherwise finish after 1500 ms, requires completion under 1200 ms, and checks the provider process has exited.
- A valid generated body has nonempty `## Summary` and `## Extraction Candidates` sections. Empty output, unstructured prose, empty sections, and frontmatter-only output fail before replacing the cache. `None.` remains a valid extraction-candidate body.
- A failed forced refresh leaves the previous usable summary at its original path, byte-for-byte unchanged. The old summary can be moved to trash only after a valid replacement has been generated.

## Expected RED results against the baseline

Expected total: 25 tests, with 2 passing legacy-compatibility tests and 23 behavior failures.

| Tests | Expected assertion failure |
|---|---|
| Legacy excerpt and legacy summarizer input | Pass; preserve established human/assistant behavior. |
| Claude user, Codex, generic excerpts | Missing user/assistant text in excerpt. |
| Codex metadata/tool/event filtering | Missing canonical conversation text. Once formats are supported, exact excerpt equality guards against duplication and metadata contamination. |
| Mixed content blocks and generic Unicode excerpt | Missing conversational text; Unicode boundary expectations protect the decoder integration. |
| Claude, Codex, generic summarizer input | Provider prompt omits the user or both conversation turns. |
| Unsupported transcript with usable excerpt | Provider prompt lacks fallback text and result incorrectly reports complete input. |
| Unsupported transcript without fallback | Command incorrectly succeeds and invokes the provider. |
| Malformed recognized message plus valid message | Result incorrectly reports `degraded: false`. |
| Custom executable arguments | Provider receives `-p --model haiku`. |
| Explicit JSON arguments | Provider still receives implicit Claude arguments. |
| Three malformed argument settings | Command incorrectly succeeds instead of rejecting configuration before invocation. |
| Four invalid forced-refresh bodies | Command incorrectly succeeds and replaces the previous usable summary. |
| Empty first generation | Command incorrectly succeeds and caches empty output. |
| Provider deadline | Command incorrectly succeeds after the fixture delay and replaces the previous summary. |

These are behavioral failures using existing imports and executable code paths. Any import failure, fixture exception, or type error is a test defect to correct before I1 is released.

## Mutation checks

- Dropping a user turn, using only legacy record types, accepting a tool record, or decoding mirrored events twice changes exact excerpt or provider-input assertions.
- Treating undecodable or malformed conversation input as complete changes fallback/degradation assertions.
- Adding vendor flags to a custom command or shell-parsing argument strings changes the observed argument vector.
- Skipping output validation or moving the cache before a failed generation breaks cache-content assertions.
- Omitting the deadline, failing to stop the provider, or leaving its output streams blocking breaks bounded-failure assertions.
