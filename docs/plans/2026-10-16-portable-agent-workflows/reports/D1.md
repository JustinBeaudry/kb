# D1: Portable skill and documentation

## Changes

- Reduced `skills/kb/SKILL.md` to a portable trigger/router: vault discovery, runtime prerequisites, the map → select → get-node evidence loop, direct get for a known page, and trust/mutation boundaries.
- Added relative on-demand guides under `skills/kb/references/`: `query.md`, `ingest.md`, `maintenance.md`, and `sessions.md`. The query guide is the shared route for every harness; optional qmd only contributes CLI hints.
- Made `skills/extract/SKILL.md` and `skills/refine/SKILL.md` small routers to those same guides. All five `commands/*.md` files are optional wrappers pointing to the shared operation documentation.
- Removed automatic query filing and query-log edits, the page/link quotas, mandatory qmd/MCP/Claude prerequisites, and forced broad ingestion cascades. Queries preserve knowledge; existing CLI operational cache/log writes remain allowed.
- Kept vault-specific schema, page types, wikilink conventions, provenance, index/log formats and working-set policy in `templates/KB.md`, with no duplicated provider or alternate-search workflow.
- Rewrote README setup around the standalone CLI and portable skill. It explicitly distinguishes the compiled binary from the Bun source/bin entry points, and documents optional native integration separately.
- Documented the accepted interfaces: complete 16384-byte curated wire budget; `--budget > KB_RETRIEVAL_BUDGET > KB_MAP_BUDGET (map only) > default`; structured continuations and absolute source lines/result offsets; lazy absent/invalid config; eager curated context/index only; supported JSONL transcript shapes; generic executable/stdin/explicit-argv provider contract; per-invocation timeout; structured summary validation and failed-cache preservation.
- Session guidance checks already filed facts before retrying interrupted extraction and leaves failed/incomplete sessions pending. Access approval is tied to the existing user request, not a mandatory repeated confirmation. New summary generation may need a provider; core queries and cached summaries do not.

## Correction 1 from actual agent behavior

The initial A09 agent trial exposed unnecessary whole-page retrieval and host display truncation. Updated only the main skill and query guide to prefer question/heading-specific map queries, read the smallest sufficient section, stop when evidence suffices, and distinguish wire truncation from the harness display limit. A larger response should be saved and parsed locally only when actually necessary. No scenario, expected outcome, production code, or evaluator changed.

Root reran the 11 documentation contracts (all pass) and six fresh current-agent trials against a frozen revision. The long-page task fell from 17 calls/605,678 bytes to 2/1,126 with correct evidence. Small-task efficiency was mixed; see `A1.md` for all observations and limits. The final entrypoint is 62 lines/3,182 bytes, versus 146/8,730 at base; the vault template is 173 lines/7,247 bytes, versus 439/20,102. These are file-size observations, not total token-cost measurements.
