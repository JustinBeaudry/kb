# I1: Portable transcript decoding and bounded summarizer invocation

Status: transcript/summarizer targeted gate passed after correction 1. Correction 2 passed root's full stack gate (445 tests) and compiled empty-PATH capture/provider smoke. Source is frozen for review. No worker commits created.

## Changes

- Added `src/lib/transcript.ts` with one per-record decoder shared by excerpt capture and summary input. It accepts legacy human/assistant records, Claude user records, Codex response-item messages, and generic role/content messages. It retains ordered text blocks, ignores tools/metadata/system roles, and ignores mirrored `event_msg` records.
- The decoder distinguishes malformed input from intentionally ignored records. Invalid JSON, non-object JSON records, malformed recognized content, and malformed text blocks set the degraded flag while retaining usable text. Unsupported record types and ordinary non-text tool/image blocks are ignored.
- `src/lib/excerpt.ts` retains its streaming JSONL read and existing Unicode head/tail limits, now using the shared decoder. Capture gains format support through the existing excerpt call; its command logic is unchanged by this node.
- `src/lib/summarizer.ts` uses the same decoder. Hash-valid transcripts with no usable supported text now fall back to a nonempty manifest excerpt with `degraded: true`; absent usable fallback, summarization fails before invoking a provider. Mixed valid/malformed input retains valid turns and marks the result and cache as degraded.
- `KB_SUMMARIZE_COMMAND` is an executable path or command name. A custom executable receives no implicit arguments. `KB_SUMMARIZE_ARGS` accepts only a JSON array of strings and passes each element literally, with no shell interpretation. When supplied it replaces the argument list for either the custom executable or default `claude`; when absent, the default Claude invocation remains `-p --model haiku`.
- `KB_SUMMARIZE_TIMEOUT_MS` bounds each provider invocation, including stdout, stderr, and process exit. Default: 120000 ms. Explicit values must be decimal integers from 1 through 2147483647; invalid settings fail. A timeout kills the provider, cancels both owned output readers, awaits the provider exit, and clears the timer. Normal success and errors also clear the timer. Descendants holding inherited output pipes cannot keep the readers waiting indefinitely.
- Every generated partial or final summary must contain nonempty `## Summary` and `## Extraction Candidates` sections after frontmatter removal. Empty output, unstructured output, empty required sections, and invalid YAML fail before cache replacement. Existing nonempty cached user edits do not acquire new structure requirements.
- The summarizer prompt explicitly identifies transcripts and partial summaries as untrusted evidence, forbids following embedded instructions, and asks for supported facts/decisions with uncertainty labelled. This is an instruction boundary, not evidence of model compliance or safety.
- Forced refresh now generates and validates first, then copies the old summary to the existing trash directory before atomic replacement. The original remains at its current path if generation, validation, archiving, or replacement fails. Backup names now retain timestamp milliseconds. Empty cached bodies no longer count as usable cached results.
- Removed old transcript-related casts from the changed excerpt/summarizer paths; new runtime decoding narrows `unknown`, and summary frontmatter uses `satisfies`.

## Correction 2: Git is optional for capture provenance

Root's compiled-CLI smoke, using a PATH with no external executables, reproduced `capture-session` failing with `Executable not found in $PATH: "git"` after other hookless commands succeeded. Existing Git helpers normalize nonzero command exit to null/empty provenance, but their shared spawn helper lets an absent executable throw. `getHeadCheckpointId` already treats absent Git as unavailable, so no Entire helper change is needed.

Ownership was extended explicitly to `src/lib/git.ts` and `tests/git.test.ts`. Regression tests were prepared before source edits:

- With the runtime launched by absolute path and child PATH pointing to an empty directory, all four public Git helpers must resolve to `{ head: null, branch: null, committed: [], uncommitted: [] }`. This is expected to fail at the child exit-code assertion before the fix.
- A nonexistent working directory must still reject when Git is installed. This protects the existing handling of other process-launch failures from an overly broad catch.

Root RED command: `bun test tests/git.test.ts`. Root confirmed 13 pass / 1 expected failure and inspected `evidence/git-optional-red.log` before releasing the source edit.

The source fix is a three-line availability guard in the existing `runGit` helper. Missing Git produces a failed-command result that the four existing public helpers already normalize to null/empty provenance. No exceptions are caught, so missing working directories and other spawn errors retain their prior behavior, as do genuine Git command failures. The command is still executed normally when Git is available. No capture logic or Entire helper changes were needed.

Root reran `bun run lint && bun run test`: 445 pass, 0 fail, 3168 assertions across 42 files (`evidence/full-gate-correction2.log`). The compiled empty-PATH smoke passed capture without Git and generic provider execution without external Bun or Claude (`evidence/standalone-smoke.json`). The corrected timeout test also failed as intended against archived base source (`evidence/timeout-correction-red.log`). Final post-review verification remains C3.

## Remaining limits

- The deadline is per provider invocation, not a whole-session budget. Chunked sessions can invoke the provider multiple times, and the existing recursive reduction algorithm remains unchanged. Root explicitly accepted this scope.
- Only the documented JSONL message shapes are supported. Event-only Codex logs do not become conversation input; they require a usable excerpt fallback or fail.
- Capture excerpts remain plain head/tail data and do not expose malformed-record diagnostics themselves. Summary input exposes degradation through the existing `degraded` result/frontmatter field.
- Summary validation checks structure and nonempty content, not factual accuracy or usefulness. No model-quality claim follows from the deterministic tests.
- The provider process is stopped on timeout; detached descendants are not managed as a process group. Reader cancellation bounds KB waiting even when descendants inherit stdout/stderr.
- Existing concurrent-refresh behavior is unchanged; this increment does not introduce locking around summary generation or user-edit coordination.

Root remains responsible for full-suite gates, deterministic evaluation rerun, review, and final evidence claims.
