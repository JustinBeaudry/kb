## Measurements and limits

Main skill: 146 lines/8730 bytes -> 62 lines/3182 bytes. Vault template: 439 lines/20102 bytes -> 173 lines/7247 bytes. These are file footprints, not total prompt-token or cost measurements.

Representative deterministic wire outputs: `get` 209233 -> 16218 bytes; `get-node` 209236 -> 16316 bytes; `recall` 24568 -> 15641 bytes; absent-config startup 608 -> 284 bytes. Large curated results now expose continuation or a concrete budget remedy instead of oversized success.

The review caught an intermediate recall allocation regression. On the fixed 64-file/6,272,512-byte/64,000-match fixture, median peak RSS fell from 348,749,824 to 32,620,544 bytes after correction; wall time fell from 127.60 to 29.45ms. Original base was 31,653,888 bytes/27.96ms but silently capped results at 20. Final returns 21 chunks with continuation. All three samples per version and the reproducible probe are under `../evidence/recall-profile-*`; these are fixture observations, not general latency guarantees.

Eighteen actual agent trials cover six preselected scenarios across base, initial current and refined instructions. All answers meet their expected outcomes; no unauthorized knowledge writes occurred. The long-page task improved from baseline 4 calls/419678 bytes to refined 2 calls/1126 bytes. Small-task efficiency is mixed. Trials were development cases in one host, preceded the later R1 source corrections, and used a deterministic summary provider. See `A1.md` for exact conditions and all results. Best-in-class, held-out, cross-harness, token-cost and real-provider summary-quality claims remain unproven.

Other implementation limits remain documented: provider deadlines are per invocation, detached descendants are not process-group managed, summary refresh concurrency is unchanged, and continuations assume unchanged vault content.
